1 Working with Dates and Times in Python

1.1 A comprehensive, example-driven reference for time-based data

Dates and times appear in sales records, transactions, web events, appointments, sensor readings, financial data, staffing schedules, and many other business datasets. Before analyzing such data, we must be able to create, parse, validate, index, align, aggregate, and transform timestamps reliably.

This notebook reviews the most commonly used date/time capabilities in:

  • Python's built-in datetime module
  • dateutil for flexible parsing and calendar-aware arithmetic
  • NumPy datetime64 and timedelta64
  • pandas Timestamp, Timedelta, Period, DatetimeIndex, and related tools
  • Matplotlib date locators and formatters

The emphasis is on learning by example, especially when imported dates do not follow a standard format and when calendar components must be extracted to create useful features.

1.1.1 Learning objectives

By the end, you should be able to:

  1. Distinguish dates, clock times, timestamps, durations, and periods.
  2. Parse standard, nonstandard, mixed, ambiguous, and invalid date/time text.
  3. Import timestamps from CSV, Excel-style values, Unix epochs, and separate columns.
  4. Create regular and business-calendar date ranges.
  5. Index, filter, slice, align, and join observations by time.
  6. Extract calendar and clock components and design time-based features.
  7. Compute lags, changes, elapsed times, and rolling summaries.
  8. change frequency using asfreq() and resample() appropriately.
  9. identify missing, duplicated, irregular, and misordered timestamps.
  10. Work safely with time zones and daylight-saving transitions.
  11. Validate a time-based dataset before using it in later analysis.

Run the notebook from top to bottom. Then change examples, introduce errors, and observe what happens.

1.2.1 How to read the function calls in this notebook

A Python function call has the general form function(argument, parameter=value). For example:

pd.date_range("2026-01-01", periods=7, freq="D")
  • pd.date_range is the function being called.
  • "2026-01-01" is a positional argument. Its meaning is determined by its position; here it is the starting date.
  • periods=7 is a keyword argument requesting seven timestamps.
  • freq="D" is another keyword argument specifying daily frequency.
  • The function returns a DatetimeIndex; it does not change an existing table unless its result is assigned to a variable.

Throughout the notebook:

  • Text values appear inside quotation marks: "D", "date", and "UTC".
  • Numbers and Boolean values do not: periods=7, dayfirst=True.
  • Most pandas operations return a new object. Save it with assignment, such as clean = raw.sort_values("date").
  • Methods follow an existing object: sales.sort_index() calls the sort_index method on sales.
  • Square brackets select data: df["sales"] selects one column and df[["sales", "cost"]] selects two columns.

When a parameter is omitted, Python uses its default. Defaults are convenient, but date/time defaults are not always appropriate for the source data. This notebook therefore specifies important choices explicitly.

1.3 1. Python date, time, datetime, and timedelta

The standard library establishes the vocabulary used by every other package. A date answers which calendar day, a time answers which clock time, a datetime combines both, and a timedelta measures elapsed duration. Choosing the correct object prevents ambiguous calculations later.

1.3.0.1 Function guide: constructing standard-library temporal objects

Constructor Required components What it represents
date(year, month, day) calendar components A day without a clock time
time(hour, minute, second=0) clock components A clock time without a date
datetime(year, month, day, hour=0, minute=0, second=0) date and optional time components A specific calendar-and-clock reading

Components are integers, not strings. Months run from 1–12; hours use the 24-hour clock from 0–23. Invalid dates such as date(2026, 2, 30) raise an error immediately. Attributes such as .year, .month, and .hour retrieve individual components. weekday() returns Monday as 0 through Sunday as 6.

1.3.0.2 Function guide: timedelta

timedelta represents a fixed elapsed duration. Common parameters include days, seconds, minutes, hours, and weeks; they can be combined in one call. Adding a duration to a datetime produces another datetime, while subtracting two datetimes produces a timedelta.

  • .days returns only the whole-day component.
  • .seconds returns the remaining seconds after whole days and can therefore be misleading by itself.
  • .total_seconds() returns the entire duration expressed in seconds, including all days.

A fixed duration is not a calendar rule: 30 days is not always the same as one calendar month.

# Durations support date arithmetic.
next_session = class_meeting + timedelta(days=7)
ninety_minutes_later = class_meeting + timedelta(minutes=90)
time_until_next = next_session - class_meeting

print("Next session:", next_session)
print("Class ends:", ninety_minutes_later)
print("Elapsed:", time_until_next)
print("Elapsed days:", time_until_next.days)
print("Elapsed seconds:", time_until_next.total_seconds())

1.3.1 Parsing strings and formatting dates

Parsing converts text to a datetime. Formatting converts a datetime to text. %m means month while %M means minute—a frequent source of errors.

1.3.1.1 Function guide: strptime() and strftime()

  • datetime.strptime(text, format) parses text into a datetime.
  • datetime.strftime(format) formats a datetime as text.

The format string describes the text exactly. %m means month, %d day, %Y four-digit year, %H 24-hour clock, %I 12-hour clock, %M minute, and %p AM/PM. Punctuation and spaces must also match. A common mistake is confusing %m (month) with %M (minute).

Use parsing when text must become computable time data. Use formatting only when producing labels or exported text—the formatted result is a string again.

raw_text = "08/27/2026 06:30 PM"
parsed = datetime.strptime(raw_text, "%m/%d/%Y %I:%M %p")

print(parsed)
print(parsed.strftime("%A, %B %d, %Y at %I:%M %p"))
print(parsed.isoformat())

2026-08-27T18:30:00

1.4 2. dateutil: flexible parsing and calendar-aware arithmetic

Python's fixed timedelta cannot express an irregular calendar unit such as “one month.” dateutil fills that gap and can also interpret human-entered date strings. Its flexibility is valuable, but inference should never replace a known, documented format.

dateutil is commonly installed with pandas. Its parser recognizes many human-readable formats, while relativedelta performs calendar-aware arithmetic such as “one month later.” Flexible inference is convenient, but ambiguous numeric dates still require an explicit rule.

1.4.0.1 Function guide: parser.parse() and relativedelta()

parser.parse(text) attempts to infer a human-readable layout. Important options include:

  • dayfirst=True: interpret ambiguous numeric forms as day/month/year.
  • yearfirst=True: prefer year/month/day when several interpretations are possible.
  • fuzzy=True: allow unrelated words around a recognizable date; use cautiously.

relativedelta(months=1) applies a calendar rule rather than a fixed duration. Other useful parameters include years, months, weeks, days, and weekday. Singular forms such as month=6 replace a component; plural forms such as months=6 add an amount. This difference is subtle and important.

from dateutil import parser
from dateutil.relativedelta import relativedelta, FR

print(parser.parse("March 15, 2026"))
print(parser.parse("15 March 2026 at 2:30 PM"))
print(parser.parse("15/03/2026", dayfirst=True))

month_end = datetime(2026, 1, 31)
print("30 fixed days later:", month_end + timedelta(days=30))
print("1 calendar month later:", month_end + relativedelta(months=1))
print("Next Friday:", month_end + relativedelta(weekday=FR(1)))

1.5 3. NumPy datetime64 and timedelta64

NumPy represents dates as numeric counts from an origin using a declared resolution. You rarely need to construct these arrays directly, but recognizing datetime64[ns], datetime64[D], and NaT makes pandas dtypes and error messages much easier to understand.

NumPy provides compact vectorized date/time arrays. pandas builds on NumPy's temporal ideas, so these dtypes commonly appear when inspecting imported or transformed data.

1.5.0.1 Function guide: NumPy date/time dtypes

np.array(values, dtype="datetime64[D]") converts all values to a date/time array at day resolution. The unit inside brackets controls precision:

  • Y, M, W, D: year, month, week, day
  • h, m, s: hour, minute, second
  • ms, us, ns: millisecond, microsecond, nanosecond

np.timedelta64(3, "D") creates a duration of three days. np.diff(array) subtracts consecutive elements. astype("datetime64[h]") changes representation to hourly resolution; it does not invent information more precise than the original data.

np_dates = np.array(["2026-01-01", "2026-01-08", "2026-01-15"], dtype="datetime64[D]")

print("Dates:", np_dates)
print("Differences:", np.diff(np_dates))
print("Add three days:", np_dates + np.timedelta64(3, "D"))
print("Hourly resolution:", np_dates.astype("datetime64[h]"))
print("Missing NumPy date:", np.datetime64("NaT"))
Dates: ['2026-01-01' '2026-01-08' '2026-01-15']
Differences: [7 7]

The unit in brackets matters: datetime64[D] uses day resolution, whereas datetime64[ns] uses nanosecond resolution. pandas normally provides a friendlier interface for business data.

1.6 4. pandas temporal objects

pandas supplies the main tools used with tabular time-based data. Timestamp represents a point, Timedelta represents elapsed time, and Period represents a labeled span such as a month or quarter. pd.to_datetime() converts imported values into these usable temporal representations.

1.6.0.1 Function guide: pandas scalar time objects

  • pd.Timestamp(value) creates one point in time and is pandas' counterpart to datetime.
  • pd.Timedelta(value) creates one elapsed duration. It accepts readable text such as "2 days 6 hours".
  • pd.Period(value, freq=...) creates a labeled span. The required freq tells pandas whether the label represents a month, quarter, year, or another period.

Period.start_time and Period.end_time convert the span to boundary timestamps. Adding 1 to a monthly period moves exactly one month, because the period already knows its frequency.

ts = pd.Timestamp("2026-08-27 18:30")
duration = pd.Timedelta("1 day 2 hours 15 minutes")
month = pd.Period("2026-08", freq="M")

print(ts, type(ts))
print(duration, type(duration))
print(month, type(month))
print("Timestamp + duration:", ts + duration)
print("Next monthly period:", month + 1)
print("Month begins:", month.start_time)
print("Month ends:", month.end_time)

1.6.1 Ambiguous numeric dates: a serious data-quality risk

Interpretation: both conversions succeed, but they produce different dates. A parser cannot know the source convention from these values alone. Successful parsing therefore does not prove correct parsing.

ambiguous = pd.Series(["01/02/2026", "03/04/2026"])

comparison = pd.DataFrame({
    "raw": ambiguous,
    "month_first": pd.to_datetime(ambiguous, format="%m/%d/%Y"),
    "day_first": pd.to_datetime(ambiguous, format="%d/%m/%Y")
})
comparison
raw month_first day_first
0 01/02/2026 2026-01-02 2026-02-01
1 03/04/2026 2026-03-04 2026-04-03

Always specify the known format when dates are ambiguous. Successful parsing does not guarantee correct parsing.

1.7 5. Creating date ranges and understanding frequency

A regular date range defines the expected time grid. The frequency is not merely display formatting: it determines which timestamps exist, where periods begin or end, and how later alignment and aggregation behave.

1.7.0.1 Function guide: pd.date_range()

pd.date_range() creates an evenly spaced DatetimeIndex. Specify a start and then either an end or a number of periods.

Parameter Example Meaning
start "2026-01-01" First boundary
end "2026-01-31" Last boundary
periods 7 Number of timestamps
freq "D", "h", "MS" Spacing or calendar rule
inclusive "both", "left" Which endpoints are allowed
tz "America/Los_Angeles" Optional time zone
normalize=True — Move start/end to midnight first

Supply exactly three of start, end, periods, and freq; pandas can infer the fourth in many cases. For time-series work, explicitly specifying freq usually makes the intended calendar clearest.

daily = pd.date_range("2026-01-01", periods=7, freq="D")
business_days = pd.date_range("2026-01-01", periods=7, freq="B")
month_starts = pd.date_range("2026-01-01", periods=6, freq="MS")
month_ends = pd.date_range("2026-01-01", periods=6, freq="ME")

1.7.0.2 Parameter nuance: inclusive

When both start and end are provided, inclusive controls whether the endpoints appear:

  • "both": include start and end.
  • "left": include start, exclude end.
  • "right": exclude start, include end.
  • "neither": exclude both.

Half-open intervals—include the start and exclude the end—are especially useful for adjacent reporting periods because a boundary timestamp belongs to only one interval.

# Inclusive endpoints can be controlled explicitly.
print(pd.date_range("2026-01-01", "2026-01-05", inclusive="both"))
print(pd.date_range("2026-01-01", "2026-01-05", inclusive="left"))

1.7.0.3 Function guide: pandas offsets

Offsets apply calendar rules:

  • BDay(1): one weekday forward, ignoring holidays unless customized.
  • MonthEnd(1): move to the next applicable month end.
  • MonthBegin(1): move to the next applicable month beginning.
  • .rollforward(timestamp): move to the next valid boundary, leaving an already-valid date unchanged.
  • .rollback(timestamp): analogous movement backward.

Offsets differ from Timedelta because their elapsed duration depends on the calendar position.

1.7.0.4 Function guide: CustomBusinessDay

CustomBusinessDay(holidays=...) creates a reusable calendar offset that skips weekends and the supplied holiday dates. The object can be passed as freq to date_range().

The ordinary "B" frequency skips Saturdays and Sundays but does not automatically know an organization's holidays. A custom calendar should reflect the institution, market, or operational process represented by the data.

# Custom business calendars can account for selected holidays.
from pandas.tseries.offsets import CustomBusinessDay

holidays = ["2026-01-01", "2026-01-19"]
usc_business_day = CustomBusinessDay(holidays=holidays)
pd.date_range("2026-01-01", periods=12, freq=usc_business_day)

1.11 9. Lags, differences, percentage changes, and returns

These transformations describe relationships across time. A lag retrieves an earlier row, a difference measures absolute change, and percentage change measures relative change. Their interpretation depends on ordering and frequency: “seven rows earlier” means “seven days earlier” only on a complete daily grid.

1.12 10. Rolling, expanding, and exponentially weighted calculations

Rolling calculations summarize a moving neighborhood; expanding calculations summarize everything observed so far; exponentially weighted calculations give greater influence to recent observations. Always state whether the window counts rows (7) or elapsed time ("7D").

1.12.0.1 Function guide: moving and cumulative windows

  • window=7: seven rows; window="7D": seven calendar days.

  • center=True: label the result at the center rather than the right edge.

1.13 11. asfreq() versus resample()

Both operations change frequency, but they answer different questions. asfreq() aligns observations to a new grid without summarizing them. resample() creates time bins and applies an aggregation. Confusing them can change the meaning of the data.

These methods answer different questions:

  • asfreq() conforms data to a new time grid; it does not aggregate.
  • resample() groups observations into time bins and then applies an aggregation or transformation.

1.13.0.1 Function guide: resample()

resample(rule, ...) groups a datetime-indexed object into time bins. The rule is a frequency such as "W-SUN", "MS", or "h". An aggregation must follow, such as .sum(), .mean(), .min(), or .agg(...).

  • label="left" or "right": which bin boundary becomes the output timestamp.
  • closed="left" or "right": which boundary owns observations exactly on an edge.
  • origin: the anchor used to construct fixed-frequency bins.
  • offset: shift bin boundaries relative to the origin.

Weekly rules are anchored: W-SUN means weeks ending Sunday, while W-MON means weeks ending Monday.

1.14 12. Missing timestamps versus missing values

1.17 15. Time zones and daylight-saving time

A naive timestamp records a clock reading without identifying where it occurred. An aware timestamp identifies an instant through its time zone. tz_localize() interprets a naive clock reading in a zone; tz_convert() displays the same instant in another zone.

A naive timestamp has no time-zone information. An aware timestamp represents time in a specified zone.

  • tz_localize() attaches/interprets a time zone without changing the displayed clock reading.
  • tz_convert() represents the same instant in another time zone, changing the displayed clock reading.

1.17.0.1 Function guide: tz_localize() and tz_convert()

  • tz_localize(zone) attaches a zone to naive clock readings. It answers: “Which zone did these clock readings occur in?”
  • tz_convert(zone) changes the displayed clock time while preserving the same instant. It requires already-aware timestamps.

IANA zone names such as "America/Los_Angeles" are preferable to fixed labels such as PST, because they include historical daylight-saving rules.

  2. Normalize only documented inconsistencies.
  3. Parse with an explicit format whenever possible.
  4. Use errors="coerce" to expose failures as NaT.
  5. Inspect and report failed rows rather than silently dropping them.
  6. Confirm time zones, frequency, minimum/maximum dates, ordering, and duplicates.

Principle: never overwrite the only copy of an imported timestamp. Retaining the original text makes incorrect parsing detectable and reversible.

1.24 22. A reusable date/time audit function

1.24.0.1 Function guide: reading the audit function

This user-defined function accepts:

  • df: the DataFrame to inspect.
  • time_col: the name of the timestamp column.
  • value_cols=None: an optional list of columns whose missing values should be counted.
  • expected_freq=None: an optional frequency such as "D"; when supplied, missing expected timestamps are counted.

The function returns a labeled Series rather than changing the data. value_cols = value_cols or [] converts an omitted list to an empty list. This avoids iterating over None. The audit is a starting checklist, not proof that the data are substantively correct.

def audit_time_series(df, time_col, value_cols=None, expected_freq=None):
    """Return a compact set of checks before time-series analysis."""
    value_cols = value_cols or []
    timestamps = pd.to_datetime(df[time_col], errors="coerce")
    valid = timestamps.dropna().sort_values()

    report = {
        "rows": len(df),
        "unparseable_timestamps": int(timestamps.isna().sum()),
        "duplicate_timestamps": int(timestamps.duplicated(keep=False).sum()),
        "chronologically_sorted": bool(timestamps.is_monotonic_increasing),
        "start": valid.min() if len(valid) else pd.NaT,
        "end": valid.max() if len(valid) else pd.NaT,
        "inferred_frequency": pd.infer_freq(valid.drop_duplicates()) if len(valid.drop_duplicates()) >= 3 else None,
    }

    for col in value_cols:
        report[f"missing_{col}"] = int(df[col].isna().sum())

    if expected_freq and len(valid):
        expected = pd.date_range(valid.min(), valid.max(), freq=expected_freq)
        report["missing_expected_timestamps"] = int(len(expected.difference(valid)))

    return pd.Series(report, name="audit")

1.25.0.1 How the end-to-end workflow fits together

  1. copy() protects the original table.
  2. to_datetime(..., errors="coerce") makes invalid timestamps detectable.
  3. dropna(subset=["date"]) removes failed timestamps only after they have been saved separately.
  4. groupby(...).sum() applies the stated same-day transaction rule.
  5. sort_values() establishes chronological order.
  6. asfreq("D") exposes missing days on the expected grid.
  7. A Boolean observed column records which values were originally present.
  8. New derived columns are added without overwriting the original measurement.

Every step encodes an assumption. In a real dataset, document why that assumption is appropriate.

1.29 27. Quick-reference checklist

Before analyzing any time-based dataset, ask:

  • Is the time column truly a datetime dtype?
  • What does each timestamp represent: event time, reporting time, start, or end of a period?
  • Is the index sorted and unique—or are duplicates meaningful?
  • What is the expected frequency? Is the observed series regular?
  • Are entire timestamps missing, or only values?
  • What time zone is intended? Are DST transitions relevant?
  • How were observations aggregated and bins labeled?
  • Were imputed values clearly identified?
  • Does each lag or rolling feature use the intended historical window?
  • Are calendar conventions, business days, and holidays documented?
